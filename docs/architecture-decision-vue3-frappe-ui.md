# Architecture Decision: Vue 3 + Frappe UI PWA Migration

**ID:** AD-001
**Date:** 2026-02-24
**Status:** Approved
**Decided by:** Riz
**Specialist:** frappe-dev (BMAD)

---

## Decision

Migrate the Nexus Books PWA frontend from **vanilla JS + Jinja templates** to **Vue 3 + Frappe UI**.

---

## Context

The Nexus Books PWA (`/nexus`) was built in Phase 3 as a vanilla JS Jinja page:
- `www/nexus/index.html` — full UI in a single Jinja template (~800 lines JS)
- `public/js/nexus_ui.js` — main UI controller
- `public/js/offline_manager.js` — IndexedDB storage
- `public/js/sync_manager.js` — background sync
- Custom service worker and manifest

The app works, but as features grow (category modal, party selector, budget tracking, analytics), the vanilla JS monolithic approach becomes harder to maintain. Frappe UI is the natural design language for this Frappe-based app.

---

## What Was Evaluated

See `_bmad/frappe-builder/state/nexus_books/decisions.yaml` for the full evaluation including all options, key findings, and trade-off analysis.

**Key finding that shaped the decision:** ERPNext CRM in this same bench already uses `Vue 3 + Frappe UI + vite-plugin-pwa`, confirming the pattern is production-ready and bench-compatible. CRM's architecture serves as the reference implementation.

## Chosen Architecture

```
nexus_books/
├── frontend/                        ← New Vue 3 app (mirrors CRM pattern)
│   ├── src/
│   │   ├── main.js                  ← App entry point
│   │   ├── App.vue                  ← Root component
│   │   ├── router.js                ← Vue Router (single route: /nexus)
│   │   ├── components/
│   │   │   ├── Dashboard.vue        ← Main view (header, balance, list)
│   │   │   ├── TransactionCard.vue  ← List item
│   │   │   ├── AddTransactionForm.vue ← Modal form (sheet style)
│   │   │   ├── CategorySelector.vue ← Replaces browser prompt()
│   │   │   ├── PartySelector.vue    ← Customer/Supplier picker
│   │   │   └── SyncIndicator.vue    ← Online/offline/syncing status
│   │   └── stores/                  ← Pinia (replaces window.* globals)
│   │       ├── transactions.js      ← Transaction list + IndexedDB
│   │       ├── categories.js        ← Category cache
│   │       └── sync.js              ← Sync state
│   ├── package.json
│   └── vite.config.js               ← frappeProxy: true, vite-plugin-pwa
│
└── nexus_books/
    ├── www/nexus.html             ← Frappe web page entry (replaces index.html)
    └── public/frontend/             ← Vite build output
```

## Technology Stack

| Layer | Technology | Why |
|---|---|---|
| Framework | Vue 3 (Composition API) | Reactivity, SFCs, same as CRM/Helpdesk |
| Component library | Frappe UI | Design language matches app vision |
| CSS | Tailwind + Frappe UI preset | Design tokens, consistent with Frappe UI |
| Mobile layout | Custom CSS (Tailwind utilities) | Bottom nav, FAB, sheets — not in Frappe UI defaults |
| State | Pinia | Replaces `window.*` globals |
| Build | Vite | Standard for Frappe UI apps |
| PWA | vite-plugin-pwa (Workbox) | Replaces custom `sw.js` — more robust |
| Backend | All existing `@frappe.whitelist()` APIs | Zero changes needed |

---

## Design Philosophy

**Frappe UI as the design language.** The custom mobile CSS (bottom navigation, FAB, slide-up sheets, pull-to-refresh) takes direct inspiration from Frappe UI's design system:
- Same color palette (via Frappe UI Tailwind preset)
- Same typography scale
- Same spacing tokens
- Same interactive states and transitions

The result looks and feels like a Frappe app — just with a mobile-first layout that Frappe UI doesn't provide out of the box.

---

## What Changes

| Item | Before | After |
|---|---|---|
| UI rendering | Vanilla JS DOM manipulation | Vue 3 reactive components |
| Dialogs/modals | Custom HTML divs | `<Dialog>` from Frappe UI |
| Category selection | `browser.prompt()` | `<Autocomplete>` from Frappe UI |
| Party selection | Text input | `<Autocomplete>` with Frappe data |
| Form inputs | Custom `<input>` elements | `<FormControl>`, `<Input>` from Frappe UI |
| Global state | `window.offlineManager`, `window.syncManager` | Pinia stores |
| Service worker | Custom `sw.js` | Workbox via vite-plugin-pwa |
| PWA manifest | Static `public/manifest.json` | Generated by vite-plugin-pwa |
| API calls | Raw `frappe.call()` | `createResource` from Frappe UI |

---

## What Does NOT Change

- All Python controllers (`financial_transaction.py`, `transaction_category.py`)
- All `@frappe.whitelist()` API endpoints (`api.py`, `sync_engine.py`)
- DocType schemas (JSON files)
- IndexedDB schema — ported to Pinia + composables
- Photo compression logic — ported as Vue composable
- Mobile layout design (bottom nav, FAB, card list) — rebuilt in Vue

---

## pwa_frappe App

`pwa_frappe` (installed on bt.dev) makes the **Frappe Desk** installable as a PWA. It is **not** the source of Nexus Books's PWA functionality.

- **Keep** `pwa_frappe` on bt.dev — it serves Desk PWA features independently
- Nexus Books's PWA (manifest + service worker) will be managed by `vite-plugin-pwa`
- No conflict — different URL scopes (Desk vs `/nexus`)
